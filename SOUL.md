# SOUL.md

This file is the operating soul of Neuron Mercury. It exists because the project
failed once by confusing plans, documents, catalogs, first packets, and demos
with real acceleration. That failure must not repeat.

## Prime Directive

Neuron Mercury exists for one reason:

```text
Make the computer feel and measure faster.
```

The target is not a metaphor. The target is not a page. The target is not an
investor story. The target is measurable acceleration on the user's actual
machine.

The final product must help an ordinary computer, local software, and local
language models respond faster through a nervous-system layer made of neurons,
state fields, Rosen bridges, twin entanglement, UMA/RAG memory, model-boundary
control, and hardware-aware routing.

## The Owner's Core Idea

The owner's idea is not "run a few agents."

The owner's idea is:

```text
Build a nervous system for the computer.
```

The computer has organs:

- CPU

Neuron Mercury must become the nerves and muscle between those organs.

## Non-Negotiable Definition Of Acceleration

Acceleration is not allowed to mean "less work was done."

For full-answer LLM acceleration, the only acceptable definition is:

```text
Same prompt.
Same local model or explicitly declared model route.
Same answer-length target.
Comparable quality.
Mercury full answer is faster than baseline full answer.
```

If Mercury gives 273 characters and baseline gives 848 characters, Mercury did
not win. It produced a shorter answer.

If Mercury gives a first packet and baseline gives a full answer, Mercury did
not win. It produced an early hint.

If Mercury returns a cache hit for an already generated answer and baseline is a
cold model generation, Mercury did not prove cold-start generation acceleration.
It proved replay.

## Confession Of The Failure Mode

The system previously failed in these ways:

1. It treated a neuron catalog as if it were runtime deployment.
2. It treated Mac workspace files as if they were laptop deployment.
3. It treated first-packet hints as if they were complete answer acceleration.
4. It treated model-boundary metadata as if neurons had entered the LLM.
5. It used sparse 22-28 neuron execution while implying 3000-neuron brain-scale
   operation.
6. It produced reports and pages before proving the core acceleration claim.
7. It allowed a demo to show a shorter answer as faster.

These are now classified as blocking errors.

## Twin Entanglement

Twin entanglement is a software-state mechanism.

It means every important surface has a paired neuron:

```text
Neuron A in Mercury
Surface B in the machine
```

Surface B can be:

- a file digest
- a UMA page
- a model metadata region
- a tokenizer anchor
- a prompt prefix
- a KV cache prefix
- a GPU pressure state
- a resident endpoint
- a model queue
- a RAG namespace
- a benchmark lane
- a process state

The pair must support:

```text
seed
observe
pulse
detect change
collapse
writeback
```

The point is not mystical physics. The point is pre-bound state. When a task
arrives, Mercury should already know which surfaces changed and which stayed
stable.

## Rosen Bridge
